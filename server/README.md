# Splits API server

Go 1.26 REST API on Postgres 18. Design: `docs/05-architecture.md`; testing rules: `docs/09-testing-strategy.md`.

## Run it

From the repository root:

```sh
cp .env.example .env      # once; keep the placeholders or change them locally
docker compose up --build
```

The server applies its embedded migrations, then logs its base URL (`http://localhost:8080`) and every route. `GET /healthz` reports liveness and `GET /readyz` reports whether the database answers.

Configuration is environment variables only:

| Variable | Meaning |
|---|---|
| `APP_ENV` | `development` locally. Required. |
| `DATABASE_URL` | Postgres connection URL. Required. |
| `HTTP_ADDR` | Listen address, default `:8080`. |
| `OTP_MODE` | `fixed` (code `123456`, development only: the server refuses to start otherwise, ADR-0016). `email` is reserved: the server refuses it until an email sender exists. |

Try the auth flow (development code `123456`):

```sh
curl -si localhost:8080/v1/auth/signup -H 'Content-Type: application/json' \
  -d '{"email":"alice@example.com","password":"correct horse battery"}'
curl -si localhost:8080/v1/auth/verify-email -H 'Content-Type: application/json' \
  -d '{"email":"alice@example.com","code":"123456"}'
curl -si localhost:8080/v1/me -H "Authorization: Bearer <access_token>"
```

## Test it

Tests run against a real Postgres (never a mock). Each test gets its own schema, dropped afterwards.

```sh
docker compose up -d postgres          # from the repository root
scripts/check.sh server                # gofmt, vet, golangci-lint (depguard: ADR-0015), go test -race, govulncheck
```

For a quick single-package run: `cd server && TEST_DATABASE_URL=… go test ./internal/httpapi/` (the URL is in `.env`).

HTTP-seam tests start the fully wired server with `apptest.Start(t)`: it runs on a fake clock (`srv.Clock.Advance` expires codes and tokens), uses cheap Argon2id parameters, and keeps the server's logs (`srv.Logs()`) so tests can check they carry IDs only. `apptest.Operations(t)` lists the contract's operations for sweeping tests. `pgtest.NewSchema(t)` gives a bare schema.

## API contract

Routes, request decoding and response types come from `api/openapi.yaml` (ADR-0012), generated by oapi-codegen into `internal/httpapi/apigen`. Change the contract first, then run `scripts/generate-api.sh` from the repository root and commit the result. CI fails if the committed code drifts. `httpapi.Server` implements the generated `StrictServerInterface`, and `apptest` validates every test response against the contract.

## HTTP middleware

Every request passes, outermost first: `X-Request-ID` (kept if valid, otherwise generated; every log line carries it as `request_id`), one access-log line (route pattern, status, duration, `user_id`), panic recovery, the 64 KB body limit, Bearer authentication, and Idempotency-Key replay. Routes need an access token unless listed in `publicRoutes` (`internal/httpapi/middleware.go`); a test keeps that list in step with the contract's `bearerAuth`. An unverified User may call `unverifiedRoutes` only. Every write by a signed-in User needs an `Idempotency-Key` (NFR-R1).

## Data access

SQL lives in `internal/store/queries/*.sql`; sqlc (pinned in `internal/store/generate.go`, config `sqlc.yaml`) compiles it into `internal/store/sqlcgen` (ADR-0014). After changing a query or a migration, run `go generate ./internal/store/` and commit the result; `scripts/check.sh server` fails on drift. `store` maps the generated rows to the domain types and implements each domain package's repository interface.

## Migrations

goose SQL files in `migrations/`, embedded in the binary and applied on startup. Forward-only (ADR-0014): add a new numbered file, never edit an applied one, and write no `+goose Down` section.
